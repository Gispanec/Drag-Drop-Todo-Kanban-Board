# Flow — Drag & Drop Kanban Board

Минималистичное приложение для повседневных задач. Независимые доски, три колонки — **Запланировано → В работе → Готово** — и локальное сохранение без аккаунта и backend.

## Возможности

- Создание, переименование, переключение и удаление досок с подтверждением.
- Задачи с описанием, приоритетом, дедлайном, тегами и редактируемым чек-листом.
- Сортировка внутри колонки, перенос между колонками, включая пустые.
- Drag Overlay, placeholder, анимация вставки, автоматическая прокрутка.
- Мышь, touch-сенсор и клавиатурное перетаскивание.
- Светлая, тёмная и системная темы; поиск и фильтр приоритета.
- Немедленное сохранение, валидация данных, защита повреждённого оригинала и экспорт JSON.
- На телефоне доска прокручивается горизонтально, колонки — вертикально; список досок открывается отдельно.

Первый запуск создаёт **пустую** доску «Мои задачи». Демонстрационные карточки не добавляются.

## Стек

React 19, TypeScript 5.9 (strict), Vite 8, CSS с переменными тем. Drag & Drop: `@dnd-kit/core` 6, `@dnd-kit/sortable` 10 и `@dnd-kit/utilities` 3. Используется стабильная legacy-линейка dnd-kit, без смешивания с новым API. Иконки — Lucide, локальный шрифт — Manrope Variable. Проверки — ESLint и Vitest.

## Требования и запуск

Node.js **22.12+ в ветке 22** или **24+**, npm и современный браузер. Проверено с Node.js 24.19.0. Для установки зависимостей нужен доступ к npm.

```bash
git clone https://github.com/Gispanec/Drag-Drop-Todo-Kanban-Board.git
cd Drag-Drop-Todo-Kanban-Board
npm ci
npm run dev
```

Откройте Local URL из вывода Vite, обычно `http://127.0.0.1:5173/`. Если порт занят, Vite выберет следующий. **Используйте один и тот же адрес и порт**: от них зависит доступ к сохранённым задачам.

Для телефона в той же Wi-Fi сети:

```bash
npm run dev -- --host 0.0.0.0
```

Откройте Network URL из вывода Vite на телефоне. При необходимости разрешите доступ в локальной сети в брандмауэре. Данные телефона и компьютера независимы.

Скрипты вызывают инструменты через Node.js напрямую, поэтому работают и в Windows-каталогах с пробелами и символом `&`.

## Управление

- **Мышь:** потяните карточку, переместив курсор минимум на 6 px. Обычный клик открывает редактор.
- **Телефон:** удерживайте ручку `⠿` в правом верхнем углу примерно 180 мс и тяните. Остальная карточка допускает обычную прокрутку. Для перехода в соседнюю колонку тяните к краю горизонтальной доски.
- **Клавиатура:** Tab до ручки карточки, Space/Enter — поднять; ↑/↓ — порядок, ←/→ — соседняя колонка; Space/Enter — положить; Escape — отменить.
- **Фильтры:** при активном поиске или фильтре перенос отключён, чтобы позиция среди скрытых задач не была неоднозначной. Нажмите «Сбросить» для сортировки.
- **Редактор:** название обязательно; Enter в поле тега или пункта добавляет элемент. Последний введённый тег/пункт сохраняется и при нажатии кнопки сохранения задачи.
- **Удаление:** задача и доска требуют отдельного подтверждения. При удалении последней доски создаётся пустая «Мои задачи».

## Хранение и надёжность

Используется `localStorage`, ключ **`flow-kanban:v1`**. Для небольшого локального MVP одной синхронной записи достаточно: доски, колонки, задачи и настройки сохраняются одним JSON-снимком. Во время перетаскивания UI показывает временное состояние; окончательный порядок записывается при отпускании. Escape отбрасывает временное перемещение.

`Task.position` — последовательный целочисленный индекс внутри колонки. При вставке, удалении и переносе позиции затронутых колонок нормализуются. Это проще дробных индексов и достаточно для локальных досок.

При загрузке проверяются схема, даты, уникальность ID, ссылки между сущностями и непрерывность порядка. Повреждённый исходный JSON сначала копируется в `flow-kanban:v1:recovery:<timestamp>`. После успешного копирования открывается новая доска. Если копия невозможна, запись блокируется. Неизвестная более новая версия также защищена от перезаписи.

При ошибке записи изменения остаются в памяти, появляется предупреждение с повторной записью и экспортом. Перед закрытием страницы выгрузите JSON. Кнопка экспорта сохраняет все доски и настройки; UI импорта в этой версии отсутствует. Для технического восстановления можно записать содержимое корректного экспортированного JSON в `flow-kanban:v1` через DevTools и перезагрузить страницу.

Задачи не отправляются на сервер. Шрифт и иконки включены в сборку, внешние CDN не нужны. Для открытия приложения нужен доступ к серверу со статическими файлами: service worker/PWA пока отсутствуют.

**Ограничения:** очистка данных браузера удаляет задачи; другой браузер, профиль, домен или порт имеют отдельное хранилище. Резервная копия в том же localStorage не защищает от очистки. Одновременное редактирование в нескольких вкладках не поддерживается: последняя запись заменяет предыдущую. Синхронизации и совместной работы нет.

## Структура

```text
src/
  App.tsx                  # Сборка интерфейса и диалогов
  main.tsx                 # Подключение хранилища и React
  models.ts                # Типизированная модель
  components/
    Sidebar.tsx            # Выбор досок
    KanbanBoard.tsx        # Сенсоры, collision detection, preview и drop
    Column.tsx             # Колонка и её зона переноса
    TaskCard.tsx           # Карточка и ручка
    TaskEditor.tsx         # Создание и редактирование
    BoardDialog.tsx        # Настройки доски
    Modal.tsx              # Native dialog и управление фокусом
  domain/board.ts          # Операции с досками, задачами и порядком
  state/store.ts           # Состояние, подписки, запись и ошибки
  storage/repository.ts    # Контракт Repository и localStorage-реализация
  styles.css               # Темы и responsive layout
  utils.ts                 # Даты, подписи, экспорт
scripts/check.mjs          # Общий запуск проверок
.github/workflows/ci.yml   # Проверки на push и pull request
```

Компоненты используют `BoardStore` и доменные действия, не обращаясь к localStorage. `Repository` предоставляет `load()` и `save()`. Будущий REST API потребует асинхронного адаптера и обработки загрузки/конфликтов в store; модель, операции порядка и основные UI-компоненты можно сохранить.

## Проверки

```bash
npm run lint
npm run typecheck
npm run test
npm run build
# Все проверки одной командой:
npm run check
```

Vitest покрывает CRUD, независимость досок, удаление последней доски, переносы в начало/конец/пустую колонку, вставку между карточками, неизменяемость исходного состояния, 300 перемещений, загрузку/сохранение, повреждённый JSON, запрет storage, неизвестную версию и повторную запись после ошибки. Браузерные сценарии и ограничения проверки — в [docs/verification.md](docs/verification.md).

В GitHub Actions запускаются те же lint, tests, typecheck и build. Секреты для CI не нужны.
